01 / The handoff path

Continue the work.
Keep ownership explicit.

A Relay session tracks a conversation and its active profile. Choose your fallback order; Relay verifies when a handoff is allowed.

  1. 01

    Start a managed conversation

    Set up isolated profiles, choose their order, then launch Claude Code or Codex through Relay.

    relay claudeorrelay codex
  2. 02

    Supervise the active profile

    Relay tracks the session owner and provider usage signals. Unknown or unverified usage does not trigger an automatic handoff.

    Read the eligibility rules →
  3. 03

    Hand off when verified

    On verified exhaustion, Relay checks the next eligible profile, confirms the source has stopped, and verifies the target.

    Or switch manually →

Any handoff involving Codex

02 / Safety before availability

A handoff needs evidence.

Relay fails closed when usage, process identity, or target verification is uncertain. It does not infer exhaustion from vague percentages or bypass provider limits.

Architecture ↗Security model ↗
One active owner per Relay session
Ownership and process checks guard each transfer. Multiple sessions can share a project; Relay does not serialize file edits across them.
Provider-owned authentication
Claude and Codex use isolated profile directories. Relay never reads, copies, or routes your credentials.
Journaled, recoverable transfers
Handoffs record their state. Diagnostics and explicit recovery use that evidence to determine a safe next step.
Local supervision
No Relay-operated server. Provider communication stays with your installed Claude Code and Codex tools.
