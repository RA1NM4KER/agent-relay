One writer. An ordered fallback list.

Relay re-checks the priority order only when the current writer blocks. Until then, it stays put.

Simulated timeline
#1Claude Primary
#2Claude Backup
#3Codex Backup
  1. Claude Primary is Current and reaches 100%. It is Exhausted and resets in 1h 45m.
  2. Relay checks the priority order. Claude Backup becomes Current (session continuation, Claude → Claude). Claude Primary is Reset pending.
  3. Claude Backup exhausts before Claude Primary resets. Relay checks again: Primary is unavailable, so Codex Backup becomes Current (state continuation, Claude → Codex).
  4. Claude Primary's reset completes and it is Ready, but Codex Backup stays Current: the current writer stays put.
  5. Codex Backup exhausts, seen by Relay's periodic Codex check. Relay checks again and Claude Primary is Current once more (state continuation, Codex → Claude).

Claude exhaustion is event-driven through Relay's Claude integration. Codex usage is checked periodically while Relay supervises the Codex session.

What Agent Relay guarantees

01

Honest continuity

Claude → Claude continues the same Claude session. Between Claude and Codex, work continues from a state bundle: a new session on the other provider, not the same native conversation.

02

Local credentials

Authentication remains provider-owned. Relay never reads or stores your OAuth tokens, cookies, or keys.

03

One writer

Relay enforces a single writer per project. The current writer is sticky: it stays active until it blocks, with no eager fail-back.

How it works

Three steps, once.

01

relay setup

Log in to your Claude and Codex profiles, each in its own isolated home, and set one priority order.

02

Start managed work

Use relay claude or relay codex to start a new conversation on your highest-priority profile for that provider. Relay supervises it and follows ownership when a handoff occurs. relay resume continues it.

03

Automatic handoff

When the current writer is exhausted, Relay re-checks the whole priority order and hands off to the first eligible profile, Claude or Codex. Claude limits arrive as events; Codex quota is checked while Relay supervises its terminal.

$relay claude -- --dangerously-skip-permissions $relay codex -- --sandbox workspace-write

Arguments after -- go straight to that provider and stay provider-scoped across handoffs. Claude's are never translated into Codex's, or the other way round.

Managed Claude sessions also show the current Relay owner in the status line: [Relay · profile].

Security

Runs locally. Credentials stay put.

Agent Relay coordinates handoffs between isolated Claude and Codex profiles on your own machine. It never becomes a party to your credentials.

  • Runs entirely on your machineno Relay-operated server; Relay does not send your session data to its own backend
  • Credentials remain provider-ownedRelay launches each provider's own official login flow
  • No token storageRelay never reads, copies, or stores OAuth tokens, cookies, API keys, or passwords
  • Transactional handoffa handoff either completes cleanly or is recovered — never left half-done
  • Single-writer safetyone active writer per project, enforced, not assumed
  • Explicit profile isolationeach account lives in its own isolated configuration directory
